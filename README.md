# topomap — 负载分担网络的多路径拓扑测绘

`topomap` 用一个逐包仿真器充当「被测网络」，路由器按真实设备的脾气应答：按流 /
按包 / 按目的地址分担、同设备多接口应答、IP-ID 递增、不应答、限速应答、TTL 处理
不规范、往返路径不对称。测绘工具只能看到仿真器返回的应答（源地址、IP-ID、外层
TTL、RTT），真实拓扑只给评测器用。

```
go run ./cmd/bench -out out            # 跑全部场景，出验收指标 + HTML 报告
go run ./cmd/topomap -scenario diamond -html out/diamond.html -json out/diamond.json
go run ./cmd/simtopo -scenario quirks  # 打印仿真器里的真实拓扑（人工核对用）
go test ./...
```

## 六个问题分别怎么解

### 1. 哪些探测字段影响分流

候选字段：源 IP、目的 IP、源端口、目的端口、协议号、TOS、IP-ID、流标签。
判定用**成对扰动**而不是随机撒包：对每个字段发一对**只有该字段不同**的探测，
看这一跳的应答设备是否改变。

- 一对里两个值都来自同一个字段，其它字段完全一致，所以「两个探测落到不同设备」
  只能是该字段参与了哈希。
- 取样是**序贯的**：连续 4 对无变化即判 `ignored`；变化率 ≥ 40% 且置信度 ≥ 0.999
  即判 `steers`；只有真正含混的字段才继续烧预算。
- 同一跳先做**相同报文重复性测试**（10 个完全相同的探测）：如果相同报文自己就
  分成不同设备，这一跳是按包分担，任何字段都无法定路，字段表直接标 `untested`。
- 汇总时按**每跳各自判定**再取证据最强的一跳，而不是把所有跳平均——只有真的有
  路由器哈希这个字段，这个字段才算 `steers`。

同一组探测里，只有被判定 `steers` 的字段才允许变化；`ignored` 的字段钉死，保证
一组探测自始至终走同一条路。要探别的分支就改 `steers` 字段。

### 2. 每一跳有几个下一跳

每个 TTL 位置维护一个「设备 → 应答次数」直方图（地址先经过同设备归并）。停止
规则是多项式抽样的缺失质量上界：

- n 个有效应答、k 个已观测分支，未被看见的分支质量 ≥ m 的概率上界为
  `(k+1)(1-m)^n`；
- 当该上界 ≤ `1-Confidence` 时判定这一跳「探全了」，否则继续采样；
- 同时要求每个已观测分支至少出现 2 次，避免一条杂散应答被当成一个分支。

`Confidence`（默认 0.95）和 `Margin`（默认 0.15）都可配。报告里给出每跳的
`observed / estimate / [lower,upper] / complete`，以及实际花了多少个探测。

### 3. 分辨按流 / 按包 / 按目的地址

- **按包**：相同的报文头（同流）重复发送仍然分裂 → `spray` 比例高。
- **按目的地址**：参考流看到的下一跳只有一个，但改目的前缀（不改端口）就换设备。
- **按流**：固定五元组稳定，改某个参与哈希的字段就换分支。
- **单一**：所有维度和所有目的前缀都只有一个下游设备。

每跳输出 `TTL / mode / branches / fields`。

### 4. 多接口地址归并成同一台设备

两条独立证据，都可以从应答报文里得到：

1. **IP-ID 递增规律**：同一设备的不同接口共用一个 ID 计数器（全局），或各接口
   计数器从同一基准起步（按地址）。于是两个地址在**相邻应答**里的 ID 差是小的
   正数；两台无关设备的 ID 差是各自基准之差，大且常为负。用窗口内的跨地址
   转移做配对检验，并要求两者应答的 TTL 位置相同。
2. **同流同跳多地址**：固定头元组在一个 TTL 上轮换应答地址，只可能是同一设备
   自己的地址池；该信号还要求候选地址在该跳有可观应答占比，并排除按包分担的跳。

不用「同 /24 前缀」作为归并依据——前缀只能提出候选，不能证明同一设备。

### 5. 识别让普通工具画错的情况

| 现象 | 识别方式 | 输出 |
|---|---|---|
| 完全不应答的路由器 | 该 TTL 邻跳有应答而它从不应答 | `silent-hop`，并在图上把跨越它的边标成虚线缺口 |
| ICMP 限速 | 该跳丢包率 > 20% 且确有应答 | `rate-limited`（区分「活着但在限速」与「死了」）|
| TTL 处理不规范 | 同一设备在两个 TTL 上都应答 / 相邻跳层级差 > 1 | `ttl-hiding`，层号以最小应答 TTL 为准 |
| 外层 TTL 不常规 | 应答外层 TTL 为 255 / > 64 / 与跳距矛盾 | `outer-ttl`，不用它推断距离 |
| 往返不对称 | RTT 随跳数增加反而骤降 | `asymmetric-return` |
| 静默跳拼接 | 跨层级 > 1 的边若存在逐层可见路径则**剪掉**拼接边 | 不产生假链路；确实无法绕开时保留并标 `skipped_hops` |

### 6. 拼图

按设备（或接口）聚合成 DAG：每个节点带层号（最小应答 TTL）和置信度；每条边带
样本数、各个方向上流出度的**分支宽度**、min/median/max RTT；每个分叉单独列出
各分支的**占比**与**相对时延差**。无应答位置保留为显式缺口，不静默压缩。

## 验收

`cmd/bench` 逐场景输出，并与**单流普通 traceroute** 对比：

- 出接口级 / 设备级的准确率（precision）、遗漏率（1-recall）、F1；
- 假链路条数（断言的邻接在仿真器里不存在）；
- 跨静默跳的边（显式标注的缺口，单独计数，不算假链路）；
- 发出的探测报文总数、使用的流数；
- 普通 traceroute 的假链路条数与设备召回。

真值口径：只统计**路径上可被观测到的**设备与地址（用仿真器穷举 TTL×头字段扫描
得到的可应答地址集合），路径上完全不回应答的路由器单列，不计入遗漏。

当前内置场景（seed 7）：

| 场景 | 探测 | 出接口 P/R | 设备 P/R | 假链路 | 缺口边 | 普通 traceroute 设备召回 |
|---|---|---|---|---|---|---|
| diamond | 2836 | 100% / 100% | 100% / 100% | 0 | 0 | 50.0% |
| multitier | 3460 | 100% / 100% | 100% / 100% | 0 | 0 | 80.0% |
| quirks | 5001 | 100% / 100% | 100% / 100% | 0 | 2 | 0.0% |
| stress | 3850 | 100% / 100% | 100% / 100% | 0 | 0 | 57.1% |
| random | 3310 | 100% / 100% | 100% / 100% | 0 | 1 | 11.1% |

`random` 场景在 seed 1..40 上全部达到：出接口级与设备级 P/R 100%，假链路 0。

`random` 是随机生成的分层网络（`-seed N`），用来验证不是对着固定拓扑调出来的；
`go test ./internal/eval` 对全部场景断言假链路为 0 且设备 P/R 100%；`go test ./internal/probe`
另外覆盖字段判定、按包/按目的分流识别、异常标记、置信度与探测量的单调关系，以及
任意 seed 下图边不会反向。

## 页面

`out/index.html` 汇总，`out/<scenario>.html` 是单场景交互页：

- 左上切换**设备级 / 出接口级**两种视图；
- 边粗细 = 分支宽度，虚线 = 跨静默跳的缺口；分叉标注占比与相对时延；
- 点任意一跳，右侧列出该设备的全部地址、同设备置信度、此处分叉的各分支宽度与
  时延，以及**原始探测记录**（TTL / 流 / 源端口 / 应答地址 / IP-ID / 外层 TTL /
  RTT，可过滤）；
- 侧栏同时给出验收指标、字段判定、每跳分流方式、每跳下一跳数量估计、设备归并
  结果和识别出的异常。

页面是单文件、无外部依赖，数据内嵌为 JSON，可直接拷贝分享。
